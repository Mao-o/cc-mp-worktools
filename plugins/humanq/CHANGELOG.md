# Changelog

## 0.12.0

### 画面 (絞り込みと検索)

- 判断待ちの件数に上限は無いまま、件数が多いときに目的の問いを探せるよう、目次の帯の下に絞り込みと検索の帯を足した (全部画面の側の処理で、サーバー・bd / br の読みは変えていない)
  - 検索欄: 題・問い (ask)・背景 (context)・選択肢の label・チケット ID を、大文字小文字を区別しない部分一致で探す (前後の空白は無視。選択肢の desc は対象外)
  - プロジェクト・種別 (判断 / 作業・確認 / 問いなし)・優先度・ラベル (`human` / `answered` 以外の全ラベル。全文) の選択。選べる値が 2 つ以上ある部品 (ラベルは 1 つ以上) だけを出す。URL の値や、データから消えた値を選んでいるときは「(該当なし)」付きで残して解除できる
  - プロジェクトの選択肢には、読めなかったプロジェクト (バナーだけの入れ物) も出す。別のプロジェクトを選んでいるときだけ、そのバナーを隠す (ほかの絞り込みでは隠さない)
  - 絞り込みは判断待ちにも回答済みにも効く。絞り込むと「N 件中 M 件を表示」(N は判断待ちの全件、M は表示中の判断待ち) と「解除」が出る。全部隠れたときは「絞り込みに合うものはありません」を出す。隠れたプロジェクトの見出しと目次のチップは出さない (チップの件数は表示中の件数)
  - ヘッダーの件数・タブのタイトル・デスクトップ通知・hook の件数は、絞り込みに関係なく全件を数える
- 状態は URL の query (`project` / `kind` / `prio` / `label` / `q`) に持つ。`history.replaceState` で書き、再読み込みで復元する。空の値は query から消し、絞り込み以外の query には触らない。localStorage は使わない
- 帯の部品は作り直さない。入力中の文字・フォーカスは、15 秒ごとの読み込みでも保たれる。選択肢の一覧は変わったときだけ書き換える (開いている一覧を閉じない)
- 絞り込みを変えたときに隠れるカードは、畳む動きを付けずに外し、現れるカードに入場の動きを付けない。隠れたカードの下書き (選択・補足) と送信失敗の表示は残り、戻ると出る。読み込みで一致しなくなったカードは、今までどおり畳んでから外す
- 検索欄で Enter を押しても、ページを読み直さない

## 0.11.0

### 画面 (アクセシビリティ)

- 見出しの階層を直した。プロジェクトの見出しを h2、節 (判断・作業・確認・回答済み) の見出しを h3 にした (今までは h1 の下が h3、その下が h2 で逆だった)。見た目と sticky はプロジェクトの見出しに付いたまま、文言と件数も変えていない
- カードの `section` に、問いの要素を指す `aria-labelledby` を付けた (問いが無いカードと回答済みのカードは題の要素)。スクリーンリーダーが「領域」としてカードを名前つきで読める
- 選択肢のボタン (`.opt`) に `aria-pressed` を付けた。選ぶたびに true / false を切り替え、下書きから戻した選択も true で出る (今までは色と枠でしか伝わらなかった)
- 補足欄に `aria-label` を付けた (選択肢があれば「補足」、無ければ「回答」。placeholder だけだった)

- トーストの `role="status"` を外した。入れ物 (`#toasts`) の `aria-live="polite"` だけで読み上げる (入れ物と中の両方が live だと読み上げが重なるおそれがあった)
- 選択肢と補足欄の枠の色を、新しい `--control-line` にした (ライト `#85827a`、ダーク `#76736a`)。背景に対して 3:1 以上 (今までの `--line` は 1.2〜1.3:1)。`--line` は区切り線に使っているので変えていない
- P1 の色 (`--p1`) をライトで `#a85a0a` にした (白に対して 5.08:1。今までは 3.91:1 で 12px の文字の 4.5:1 に届かなかった)。ダークの `#e7a65a` はもともと 7.85:1 以上で変えていない

## 0.10.0

### プロジェクトごとの CLI の決め方 (br への対応の土台。br の読み書きはまだ無い)

- `server/registry.py` に `project_kind(root, cli)` を置いた。`.beads/` の中のファイルの印だけで `bd` / `br` / `unknown` / `conflict` と理由を返す (CLI は打たない。hook とサーバーの両方が使う)。br の印: `.beads/.gitignore` の `.br_history` か `fsqlite` を含む行 (コメント行は読まない)・`.br_history/`・`*-fsqlite-ns-*`・`.br-db-*.lock`。bd の印: `metadata.json` の `database` か `backend` が `dolt`・`embeddeddolt/`。br の印だけなら br、bd の印だけなら bd、両方なら conflict、どちらの印も無く `metadata.json` の `database` が `.db` で終わるなら unknown、どれにも当たらなければ bd (今までどおり)。`issues.jsonl` の有無は使わない
- 明示の設定として、hook の env `HUMANQ_BEADS_CLI` (`bd` / `br` / `auto`、未設定は `auto`。前後の空白と大文字小文字は無視) を足した。指定に反する印があれば conflict、無ければ指定どおり。SessionStart の hook が `projects.json` の各 entry に `"cli"` (指定か null) も書き、サーバーはこの値と印で決める。不正な値は `auto` として扱い、SessionStart の出力に 1 行だけ警告する
- unknown・conflict・br のプロジェクトでは、どの CLI も起動しない。`/api/items` の各プロジェクトは `ok:false`・`writable:false`・`error` を返す (unknown・conflict は「bd と br のどちらで読むか決められない (理由)。`HUMANQ_BEADS_CLI` で指定してください」、br は「br のプロジェクトにはまだ対応していません」)。br を bd の `.beads/` に向けて打つと、エラーを出さずに空の一覧を返して `.beads/` に dolt のファイルを作るので、br は br と確定した dir にだけ打つ前提にしている
- `/api/items` の各プロジェクトに `cli` (`bd` / `br` / `null`) と `writable` を足した (既存の key は変えていない)。bd として読むプロジェクトは、読みに失敗しても `writable:true`
- `POST /api/answer`・`/api/undo` は、`writable:false` のプロジェクトに対して CLI を打つ前に 400 `{code: "readonly", op}` を返す
- `/api/summary` に `ok` と `error` を足した (既存の key は残す)。今までは読めなかったプロジェクトも `human: 0` を返し、hook が「判断待ち 0 件」と言ってしまっていた。hook は `ok:false` のとき「このプロジェクトの判断待ちを読めない: <error>」と伝え、件数は言わない。UserPromptSubmit は読めなかった応答で、伝えた回答の記憶を消さない
- 設定や印が変わったときは、キャッシュの時間内でも読み直す (ファイルを見るだけ)

### 変えていないもの

- bd のプロジェクトの読み書き・bd の argv・画面・CSP は変えていない (サーバーが打つ bd の argv の列の固定は、テストを変えずに通る)。画面のバナーの文言は 0.8.0 で CLI に依らない形になっている

### テスト

- `tests/test_project_kind.py` を足した。判定の各行 (br の印 4 種と、`.gitignore` の 2 語・bd の印・両方・印なしの SQLite の形・何も無い形・`issues.jsonl` だけ・コメント行だけの `.gitignore`・明示の 3 値と不正値) を 1 件ずつ、偽の bd・br を PATH に置いて、bd の形の dir では br が 1 回も呼ばれないこと、br・unknown・conflict ではどの CLI も呼ばれないこと、`HUMANQ_BEADS_CLI=br` を bd の形に向けると conflict で `.beads/dolt` が作られないこと、`writable:false` への POST が CLI を呼ばずに 400 readonly になること、summary の `ok:false`、hook の出力が「0 件」と言わないこと、不正値の警告が 1 行だけなことを固定した

- 画面は、トーストの「取り消す」では成功の応答の署名を、回答済みのカードでは一覧の署名を `/api/undo` に付けて送る。サーバーは今の最後の `[humanq]` コメントの署名と照合し、違えば何も書かずに 409 `{code: "stale", op: "undo"}` を返す。画面は「取り消しませんでした。この回答はもう最新ではありません (ほかで答え直されています)」と知らせ、カードを戻さずに読み直す (回答済みのカードが今の回答で出直す)。そのチケットの前の回答の成功のトーストも閉じる
- 回答済みのカードの表示の署名に `asig` を入れた。同じ本文で答え直された回答でも、読み直しでカードが作り直され、取り消しが今の回答の署名を送る
- 一覧でコメントを読めなかったチケットの署名は空にし、どの回答とも合わないようにした (そのカードからの取り消しは断られ、読み直すと直る)。画面は署名が分からないときも空の署名を付けて送る (付けないと、署名を送らない古い画面と同じに読まれて照合されない)
- `asig` を送らない古い画面 (更新の前から開いたままのタブ) の取り消しは、今までどおり照合せずに受け付ける
- 取り消しのラベルの付け替えが途中で失敗した後に、同じ回答の署名で取り消し直すと 409 になる (最後の `[humanq]` コメントは取り消しのコメントで、回答の署名と合わない)。画面からはこの経路に届かない (失敗の後、チケットは判断待ちに出て、回答済みのカードもトーストも残らない。答え直せばラベルは直る)
- `[humanq]` のコメントを数えるとき、本文が文字列でないコメントは数えない (回答の書き込みは全部のコメントを数えるので、想定外の形の 1 件で回答を止めない)

### テスト

- サーバー: 偽の bd と本物の bd (PATH にあれば) の両方で、案 A で答える → 別のタブで取り消して案 B で答え直す → 案 A の署名で取り消す、が 409 `stale` でコメントもラベルも書かないことを固定した。あわせて、同じ本文の答え直し、回答済みの一覧の署名が回答の応答と同じこと (エージェントのコメントが前後に挟まっても)、送り直しの応答の署名、コメントを読めなかったときの署名、`[humanq]` のコメントが無い回答済みのチケット、署名を送らない取り消しを固定した。偽の bd では、署名の違う取り消しが読み (反映待ちの一覧とコメント) しか打たないことを argv で確かめ、既存の argv の列の固定 (読み → 回答 → 読み → 取り消し) を署名付きの取り消しで流しても列が変わらないことを確かめる

### できること

### 画面の動き

- 「回答する」を押すとすぐにカードを畳み、送信は裏で行う。失敗したら読み直してから戻すかを決め、書き込まれていなければ赤い枠で戻す。ほかで回答済みなら戻さない
- 描き直しはカードを key ごとに使い回す。押している最中のボタン・フォーカス・開いた本文・入力中の下書きを作り直さない。入力中のカードの更新は後回しにし、問いが変わっていれば送る前に作り直して知らせる
- 下書きは再読み込みしても残る (sessionStorage)。reduced-motion では動きを止め、失敗の目印は静的な枠で残す

### 書き込みの安全

- 待ち受けは 127.0.0.1 だけ。書き込みは、画面に埋め込んだトークンと Host の検査を通ったものだけ。CSP で外部の読み込みを禁じ、`frame-ancestors 'none'` と `X-Frame-Options: DENY` で他のサイトの iframe に入れさせない
- トークンは state dir のファイル (0600) に保存し、サーバーを入れ替えても変えない
- 送り直しで回答を二重に書かない (最後のコメントが同じ本文の `[humanq]` で 10 分以内なら、ラベルだけ直す)。ラベルの付け替えは 1 回だけ再試行し、失敗した段階と送信の種類を応答に入れる
- 見ていた問いの署名 (`qsig`) を回答に付け、問いが書き換わっていれば書き込まずに 409 を返す
- `human` と `answered` が両方付いたチケットは、最後の `[humanq]` コメントで判断待ちか回答済みかを決める。担当中 (`in_progress`) などのチケットも回答済みの一覧に出す
