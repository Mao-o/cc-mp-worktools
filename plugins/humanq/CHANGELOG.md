## 0.3.0

### 画面

- 回答が成功したら、「「<題>」に回答しました: <選んだ選択肢>」のトーストを出す (補足だけの回答は「(自由記述)」。題は頭 24 字、選択肢は 40 字で切る)。今までは成功しても何も知らせず、カードが畳まれて件数が減るだけだった
- そのトーストの「取り消す」で、回答を取り消して判断待ちに戻せる。回答済みのカードはページの下にあり、次の読み込みまで作られないが、その前でも送れる。取り消しが失敗したとき・ほかで反映済み (400 `gone`) だったときは、カードが無くてもトーストで知らせる。取り消しが失敗しても、問い直された問いに書きかけた下書きは消さない (前の答えのトーストから取り消して断られたとき、同じチケットの新しい問いの補足欄が空になっていた)。取り消しの成功には知らせを出さない。戻ったカードは空で出す (押し間違えた選択を戻すと、同じ答えを押し直しやすいため。送った回答の本文は bd のコメントに残る)
- 回答済みのカードで取り消したとき・同じチケットに答え直したとき・ほかで回答や取り消しが反映されていた (400 `gone`) ときは、そのチケットの前の回答の成功のトーストを閉じる (残すと、前の答えの「取り消す」から今の答えを取り消したり、取り消し済みのチケットで押して「ほかで回答・反映済み」と出たりする)。ほかのチケットのトーストは残す (id の頭が同じチケット、たとえば `x.1` と `x.10` も別に扱う)
- 回答の後のフォーカスは今までどおり次のカードそのものへ移し、トーストの「取り消す」には移さない (「回答する」を押した Enter のリピートや押し直しで、取り消しが押されない)
- トーストを下中央から右下へ移した。下にあるカードの「回答する」に重なっていた。幅は、カードの操作の行のボタン (「回答する」と、回答済みのカードの「取り消して判断待ちに戻す」) に横から掛からない幅にする。常時表示のスクロールバーがある画面でも同じ (幅はスクロールバーを除いた幅から決める)。幅 640px 以下では下に全幅で出し、ページの下にトーストの高さの余白を足す (最後のカードのボタンも、スクロールすればトーストの上に出せる)
- 同じ知らせを重ねない処理と、タブが見えている間だけ表示時間を数える処理は、成功のトーストにも効く。成功のトーストはチケットごとに分ける (題の頭 24 字と選択肢が同じ別のチケットの知らせを消さない)
- 成功・失敗の知らせのトーストは、同時に 3 つまで出す。4 つ目を出すときは、いちばん古いものを閉じる (閉じるボタンと同じ経路で閉じ、その「取り消す」は走らせない)。上限が無いと、幅の狭い右下の形 (幅 641〜669px) の低い画面で知らせが積み上がり、いちばん古いトーストのボタンが画面の上に出ていた。古い成功のトーストが閉じても、回答済みのカードの「取り消して判断待ちに戻す」で取り消せる

### テスト

- 偽の bd (`tests/fake_beads.py`) を足し、bd を通す読み書きのシナリオを本物の bd が無い環境でも回すようにした。送り直し・ラベルの再試行・両ラベルの向き・問い直し後の回答・担当中のチケットなどのテストは、今まで本物の bd が無い CI では全部 skip されていた。偽物は bd 1.3.4 で実測した癖 (0 件の `human list --json` は `null`、`human list` は `--label` を受け付けない、コメントは古い順、など) を持ち、失敗は env で注入する。本物の bd があれば、同じシナリオを本物でも回す
- サーバーが打つ bd の argv の列 (読み・回答・取り消し) を固定するテストを足した。bd の呼び出しを作り直しても、bd を使う人から見た挙動が変わらないことを機械的に確かめるため
- bd を通すシナリオ (本物の bd と偽の bd) を、discover のときは別のプロセスで並列に回す (`HUMANQ_TEST_JOBS`、既定 3。1 で直列)。本物の bd は 1 回の呼び出しに 0.2 秒以上かかり、直列では suite が 90 秒を超えていた。各プロセスは自分の一時のプロジェクトを持ち、親は結果 (成功・失敗・エラー・skip) をそのまま報告する。あわせて、問いのチケットは metadata とラベルを create で一緒に付け、シナリオの中の HTTP は OS が選んだポートで受ける (並列のプロセスでポートを取り合わない)。シナリオの中身と件数は変えていない。並列の道具が失敗やエラーを成功に読み替えないことを確かめるテストを足した。テストの外の失敗 (tearDownClass・class cleanup の失敗、プロセスの異常終了) も、直列のときと同じく ERROR にする。setUpClass の SkipTest は直列と同じく skip にし、setUpClass が落ちた・skip したときも class cleanup を回す (skip した後の class cleanup の失敗も ERROR にする)。setUpModule / tearDownModule を持つ module は並列にしない (各プロセスは module 単位の fixture を回さないので、直列なら ERROR になるものが通ってしまう)。各プロセスは親の起動の flag (`-W error` など) を引き継ぐ (直列なら ERROR になる警告を通さない)。`TestSuite.debug()` の経路でも、各プロセスの失敗・エラー・skip を例外として上げる。結果が時間内に来ないテストは ERROR にする。各プロセスは親と同じ作業ディレクトリで動く (相対パスの `HUMANQ_SERVER_DIR` が親と同じものを指す)
- 偽の bd は、本物の bd 1.3.4 と同じく labels を名前の順で返す (付けた順ではない)

## 0.2.0

**初版 (この marketplace での最初の公開)。** 0.1.x は公開前の試作で、配布していない。サーバーの入れ替えは版の大小で決めるため、試作の版より大きい 0.2.0 から始める。

### できること

- bd (beads) の判断待ち (`human` ラベル) を、端末の全プロジェクト分まとめて `http://127.0.0.1:8765/` の画面に出す。問いは metadata の `humanq` (問い・背景・選択肢・推奨) から描き、無いチケットは本文と自由記述欄だけを出す
- 画面で答えると、`[humanq] 回答: <label> (<key>)` のコメント (作者 `user/humanq`) を書き、`human` を `answered` に付け替える。close はしない。反映前なら取り消せる
- SessionStart: cwd から上に `.beads/` があるプロジェクトだけを登録し、サーバーが無ければ切り離して起動する。複数のセッションが同時に起動しても 1 台になる。判断待ちと回答済みの件数を Claude に伝える
- UserPromptSubmit: そのセッションで前に伝えた後の新しい回答を Claude に伝える (サーバーのキャッシュを見るだけで bd は読まない)

### 画面の動き

- 「回答する」を押すとすぐにカードを畳み、送信は裏で行う。失敗したら読み直してから戻すかを決め、書き込まれていなければ赤い枠で戻す。ほかで回答済みなら戻さない
- 描き直しはカードを key ごとに使い回す。押している最中のボタン・フォーカス・開いた本文・入力中の下書きを作り直さない。入力中のカードの更新は後回しにし、問いが変わっていれば送る前に作り直して知らせる
- 下書きは再読み込みしても残る (sessionStorage)。reduced-motion では動きを止め、失敗の目印は静的な枠で残す

### 書き込みの安全

- 待ち受けは 127.0.0.1 だけ。書き込みは、画面に埋め込んだトークンと Host の検査を通ったものだけ。CSP で外部の読み込みを禁じ、`frame-ancestors 'none'` と `X-Frame-Options: DENY` で他のサイトの iframe に入れさせない
- トークンは state dir のファイル (0600) に保存し、サーバーを入れ替えても変えない
- 送り直しで回答を二重に書かない (最後のコメントが同じ本文の `[humanq]` で 10 分以内なら、ラベルだけ直す)。ラベルの付け替えは 1 回だけ再試行し、失敗した段階と送信の種類を応答に入れる
- 見ていた問いの署名 (`qsig`) を回答に付け、問いが書き換わっていれば書き込まずに 409 を返す
- `human` と `answered` が両方付いたチケットは、最後の `[humanq]` コメントで判断待ちか回答済みかを決める。担当中 (`in_progress`) などのチケットも回答済みの一覧に出す

### テスト

- `tests/test_server.py` (unittest。bd が無ければ bd の要るテストは skip) と `tests/ui_test.mjs` (Playwright。API を台本どおりに返して画面の競合・失敗の経路を確かめる)
